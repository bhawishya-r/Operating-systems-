# 4) System Calls

## What are System Calls?

A **system call** is the interface through which a user-space program requests a service from the Linux kernel.

Applications cannot directly access privileged resources such as process management, filesystems, memory, or hardware. Instead, they request these services through system calls.

Basic flow:

```text
User Program
     ↓
System Call
     ↓
Linux Kernel
     ↓
System Resource
```

Examples of system-call operations include:

* Process creation and management
* File operations
* Memory management
* Network communication
* Inter-process communication

System calls therefore form an important boundary between **user space and kernel space**.

## Practical: Process and System Call Investigation

### Objective

To understand how a Bash script becomes a running process and how it interacts with the Linux kernel through system calls.

### Process Script

I created my first Bash script, `process.sh`, containing an infinite loop that prints a message and pauses for one second:

```bash
#!/bin/bash

while true
do
    echo "An experiment!"
    sleep 1
done
```

The script was executed inside my Kali Linux virtual machine.

### Activities Performed

1. **Created and executed a Bash process**

   * Created `process.sh`
   * Made it executable using `chmod +x`
   * Executed it from the terminal.

2. **System call analysis**

   * Used `strace` to observe system calls generated by the running program.
   * Investigated how user-space operations interact with the Linux kernel.

3. **Parent process investigation**

   * Examined the relationship between the Bash script and its parent process.

4. **Process and thread analysis**

   * Used `htop` to observe the running process and its threads.
   * Examined the process/thread hierarchy while the script was executing.

### Tools Used

* **Kali Linux** — practical environment
* **Bash** — scripting and process execution
* **strace** — system call tracing
* **htop** — process and thread observation

### Key Learning

This practical helped connect the concepts:

```text
Bash Script
     ↓
Process
     ↓
System Calls
     ↓
Linux Kernel
```

It also provided practical exposure to **process hierarchy, parent-child relationships, threads, and user-space/kernel interaction**.
